# 经管研究 Copilot

**简体中文** | [English](README.en.md)

**让研究思路更清楚，让每一步积累接得上。**

有了一个研究方向，却不知道该找什么数据；读完几篇论文，仍拿不准该怎么选指标；收到老师的修改意见，又担心一改就丢了原来的思路……

经管研究 Copilot 帮你理清研究问题、比较方案、核对证据，也把讨论和文件保存下来，让下次接着做。刚开始学习研究，可以从一个想法起步；已有研究经验，也可以把它用作项目管理助手，减少反复找材料、对版本、回忆修改原因的时间。

> 🌱 **研究准备与双引擎分析试用版，欢迎来试。** 当前优先使用 Codex。你不必先写好完整假设，也不必记住一串技能名称。

[开始试用](#开始试用) · [选一个小任务](#选一个小任务先体验) · [告诉我们哪里卡住了](#欢迎把卡住的地方告诉我们)

## 它能帮你跨过哪些坎？

| 你现在可能在想 | 一起往前走一步 |
| --- | --- |
| “我想研究企业数字化，但题目太大了。” | 把兴趣拆成值得比较的问题，说明各自需要什么证据和数据。 |
| “两篇论文都在研究风险，指标却不一样。” | 对照实际读到的定义、方法和结果，分清哪些做法适合你的问题。 |
| “合并数据前，我想先看看有没有坑。” | 检查企业年度 CSV 的重复键、缺失标记和数值异常，留下可核对的报告。 |
| “老师说我的指标不合适，怎么改？” | 比较改法的含义、数据要求和样本代价，保留原方案与修改理由。 |
| “这张回归表不显著，是不是白做了？” | 根据已有结果讨论方向、幅度和精度，分清证据不足与没有关系。 |
| “上次做到哪儿了？” | 从已保存的研究记录恢复问题、材料、待办和下一步。 |

你得到的不只是一个建议，还应能看懂：**为什么这样建议、依据是什么、哪些地方需要再核实。**

## 已有研究经验，把精力留给关键判断

一项研究做久了，耗时的往往还有这些事：这张表对应哪个版本？这次为什么换指标？上次讨论决定补什么？几个项目交替推进时，重新进入状态也需要时间。

你可以让 Copilot 帮忙：

- **把材料组织起来**：按项目管理文献、数据、方案与讨论，整理证据和待办。
- **把修改来龙去脉留住**：保留旧版本和修改理由，标明哪些下游材料需要重新核对。
- **把中断的工作接起来**：先核对当前有效记录、未解决问题和下一步，减少重复交代背景。
- **把已有结果整理清楚**：结合外部结果梳理判断依据、精度和解释范围，记录后续核查任务。

方法和结论仍由你作专业判断；助手可以整理材料、按已确认方案执行受支持的 Python 或 Stata 回归，并保留可核对的结果。正式执行范围见下文。

可以这样安排一次工作：

> 我已经有研究方案和阶段性结果。请先读取我指定的项目材料，整理当前问题、主要方案、修改理由和待办；区分已核实事实与我的说明，再按优先级列出下一步。先沿用现有研究设定。

## 开始试用

### 使用前需要准备什么？

**你需要先准备一个能读取和修改项目文件、调用工具并执行代码的 AI Agent 环境。** 例如 Codex、Claude Code，或接入 DeepSeek 等模型的 **Agent Harness**（为模型提供文件访问、工具调用和代码执行能力的运行环境）。请先配置好可用模型，并允许它访问项目目录和执行所需程序。

本项目提供研究流程、Skills 和分析工具，AI 助手及模型服务由你使用的 Agent 环境提供。当前实际宿主验收以 Codex 为主；Claude Code 已提供适配入口，其他环境的兼容性需按实际使用情况核对。

### 1. 把项目放到电脑上

在本页上方点击 **Code → Download ZIP**，或[直接下载使用包](https://github.com/jyq0221/econbiz-research-copilot/archive/refs/heads/main.zip)，下载后解压。

也可以用 Git clone 本仓库的默认 `main` 分支。**默认 clone 和 ZIP 都是可直接使用的版本**，包含研究入口、模板、工具和使用手册，不附合成测试数据、开发测试或内部实施记录。

没有自己的数据？[单独下载测试数据包](https://github.com/jyq0221/econbiz-research-copilot/releases/download/trial-data-v1/econbiz-trial-data-v1.zip)。里面有完整面板、带问题的练习版、字段说明和核对答案，按需下载即可。

### 2. 在 Agent 环境中打开整个项目文件夹

在你已配置好的 Agent 环境中，选择能看到本 README、`AGENTS.md` 和 `econbiz` 的那一层文件夹，然后新建对话，让助手读取项目入口。

只讨论选题可以先开始；检查 CSV、保存项目和恢复文件需要电脑上有 **Python 3.9 或更新版本**。不确定环境时，可以先对助手说：

> 帮我检查这个项目是否具备试用条件，用我能看懂的话说明能先做什么。

### 3. 直接说出你的问题

不用先填一张很长的表。已有材料就告诉助手在哪里；只有模糊想法，也可以从下面的任务开始。

如果助手没有按项目流程开始，可补充：“请读取本项目 AGENTS.md，按研究入口 Skill 帮我开始。”

**交付语言跟随你的需求。** 回复与最终交付物默认使用你本次请求的语言；明确指定时以指定语言为准，例如中文讨论、英文报告。不因材料是英文或 README 是中文而改变交付语言。目前手册和内置报告模板主要为中文，英文 README 不代表所有自动生成模板已完成英文适配。

## 选一个小任务，先体验

### 💡 只有一个想法，也能开始

> 我想研究企业数字化与经营风险，目前还没有数据。先帮我把这个方向拆成两三个值得比较的问题，解释它们各自需要什么数据。不清楚的地方保留待核实，暂时不用建项目。

**看看它是否帮你想清楚了：** 研究的到底是哪一种风险，几个问题有什么不同，下一步该找什么材料。

### 🔎 从自己的数据里找出需要核实的问题

> 请检查我提供的企业年度 CSV，先确认哪些列对应企业和年份，再核对重复记录、缺失值和数值异常。不清楚的字段含义先问我，不自动填零或删除记录。把盘点和讨论保存在 research-projects/first-try，保留原始数据。

**看看它是否真的做到了：** 指出具体记录、解释处理含义，并给出可以打开的报告和研究进展。

如果使用[测试数据包](https://github.com/jyq0221/econbiz-research-copilot/releases/download/trial-data-v1/econbiz-trial-data-v1.zip)，先读包内说明，把 `panel_with_issues.csv` 的位置告诉助手。它应发现重复键、缺失标记和未解释文本，并保留原始记录。完成后再打开 `核对答案.md` 对照。所有企业和数值均为合成，仅供练习。

### 📚 带一份自己的材料来

> 请读我提供的论文，说明作者怎样定义和测量核心概念，再比较这些做法能否用于我的研究。每个判断注明实际出处，分清作者发现和你的推论；读不到的部分不要补写。

**看看它是否讲清了：** 证据来自哪里、读到了哪部分、与自己的问题有什么关系。能否读取全文或联网检索，取决于你使用的 AI 工具及其已开放的能力。

## 下次继续，不用从头讲

需要保存时，每项研究会有自己的文件夹，默认位于 `research-projects/项目标识/`：

| 文件或目录 | 放些什么 |
| --- | --- |
| `研究进展.md` | 当前问题、进展和下一步；第一次查看可以先打开它。 |
| `literature/` | 文献材料与证据笔记。 |
| `data/` | 原始数据、字段说明及后续产物。 |
| `research/` | 方案、讨论、任务、决定、报告与检查点。 |

改了想法、修正了指标，旧版本也会保留。接续依靠实际保存的记录；重要讨论结束时，可以让助手明确说明保存了什么。

完成上面的数据小任务后，另开一次对话试试：

> 继续 research-projects/first-try。先根据已保存的材料，告诉我上次查出了什么、还不知道什么，以及下一步为什么值得做。

继续时仍从工具项目根目录打开。同一项研究轮流交给不同助手处理时，先结束上一方的写入。

## 这一版做到哪一步了？

**已接通研究准备、首批正式分析，以及 Word、LaTeX 和 PDF 结果交付。** 在问题、方案、文件版本和接续工具基础上，支持 Excel/CSV 接入、描述统计、固定效应回归、独立数值复核和结果报告；默认 Python，Stata 可选。

0.3.0a1 新增：按明确顺序比较已核验模型，核对真实样本差异，导出可编辑中文三线表 Word。包含变量定义、各模型描述统计和来源版本；文档生成、数值文本核对、逐页版式检查分别记录。调用流程见 [多模型比较与 Word 交付](docs/research-handbook/result-delivery.md)。默认 main 和 ZIP 使用包包含上述功能。

### LaTeX 和 PDF 结果交付

0.3.0a2 新增 LaTeX 源文件导出与 PDF 生成，已包含在默认 main 和 ZIP 使用包中。可以直接说：“把现有回归结果导出为 LaTeX 和 PDF，附上结果说明与模型公式。”支持单模型和多模型表格，保留已核验数值、来源与版本；PDF 需要可用的 XeLaTeX 环境，编译和逐页版式检查分别记录。当前支持范围与配置见 [LaTeX 交付手册](docs/research-handbook/latex-delivery.md)。

### 现在能参与回归吗？

**可以按已确认方案实际执行受支持的 Python 或 Stata 回归。** 首批支持企业年度面板的线性固定效应关联分析，包含企业/年度固定效应、传统或 HC1 标准误、单维聚类标准误。助手先核对字段、筛选规则、缺失处理与环境，再运行和复核。

| 回归工作的环节 | 当前能做到什么 |
| --- | --- |
| 运行前 | 接入 Excel/CSV，结合研究问题判断方法，核对测量和样本，给出简短处理方案。 |
| 数据处理 | 按明确口径缩尾、取对数、构造变量、检查合并；保留原值及处理记录。 |
| 实际运行 | 自动生成 Python/Stata 项目代码，冻结输入和环境，实际执行并修复技术错误。 |
| 已有结果 | 保存外部回归表，结合设定和来源讨论结果，明确标注“尚未复现”。 |
| 独立复核 | 常见处理及内置估计有独立参考；其他项目方法按实际检查范围记录，不把成功退出算作核验通过。 |
| 报告与重跑 | 生成表格及解释，保留全部结果；数据或方案变化后标记旧结果过期，并按新确认版本重跑。 |

**你可以直接交代研究问题，让助手判断方法、处理数据并编写和运行 Python 或 Stata 脚本。** 常见处理包括缩尾、ln、比率、交互项、标准化和按真实时间间隔构造滞后。助手先给简短方案，沿用已有授权连续执行并修复技术错误，交付代码、数据、结果与检查记录，见 [项目分析工作流](docs/research-handbook/project-analysis.md)。

**没有 Stata 也能使用 Python 完成分析。** 内置描述统计和固定效应可完成独立数值复核，调用见 [正式分析手册](docs/research-handbook/analysis-execution.md)；当前 Stata 路径实测 macOS arm64、Stata 19。DID、IV、权重和多维聚类由助手结合研究依据判断并编写项目代码，其通用独立核验尚未接入。结果会区分“已执行”和“已独立复核”；数值通过也不证明因果关系。

你可以说：**“请核对已有方案和数据，按已确认的样本与模型执行 Python 回归，给出独立复核记录和结果报告。”**

我们坚持几件小事：未知就保留未知，未披露不随意填零，原方案和结果留得住，研究修改说得清理由。检查通过不等于指标一定有效，研究进展也不以“终于显著了”为终点。

## 欢迎把卡住的地方告诉我们

第一次试用，完成上面一个小任务就很好。尤其想知道这三件事：

1. **哪里更清楚了？** 你是否更明白研究问题、指标或下一步？
2. **哪里仍然费解？** 哪句话太专业、哪一步不知道怎么操作？
3. **哪里没有做到？** 比如找不到输出文件、继续时漏了重要信息，或给了没有依据的判断。

👉 [填写试用反馈](https://github.com/jyq0221/econbiz-research-copilot/issues/new?template=trial-feedback.md)，也可以把这些体验直接告诉邀请你试用的同学。反馈里写下你的请求、实际回复和原本期待，就很有帮助。

GitHub 反馈会公开；不便公开的材料只需描述现象，无需贴出原始数据或完整论文。
