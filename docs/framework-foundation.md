# 框架第一阶段：状态、审计与方案关口

> 本文保留第一阶段实施记录。后续阶段 B 的实际执行能力和验收见 [阶段 B 验收](stage-b-validation.md)。

依据：已确认的《设计与制作标准》v1.1。本阶段落实可测试的核心约束，不将框架完成等同于 V0.1 完成。

## 实现决定

采用 Python 3.9+ 标准库、JSON 状态文件、CSV 输入和命令行入口。当前机器可用 Python 3.9.6，基础框架无需安装第三方依赖。后续描述统计与线性固定效应共用 Python 执行后端；数值库的选型、版本与独立参考结果核查属于下一阶段。本阶段不提供估计执行命令。

直接从完整网页产品开始会把状态约束推迟到界面之后；只建立目录和提示词无法证明约束有效。先实现独立核心，使后续界面和语言模型调用同一套程序规则。

## 模块契约

| 模块 | 输入与前置条件 | 输出 | 失败及依赖 | 验收 |
| --- | --- | --- | --- | --- |
| 数据盘点 | UTF-8 CSV、主体和期间列、声明的数值列；保留原文件 | 校验值、字段、唯一键、缺失原始标记、主体/期间覆盖、数值范围 | 重复键、空键、缺列、非有限数值等作为执行错误；不静默处理 | 注入重复键、空值、NaN、损坏行 |
| 候选方案 | 人工或上游提供的方案、真实字段清单 | 字段绑定、目标、判断、比较、规则、缺口和支持边界 | 不存在字段拒绝；不支持方法可以登记但不能获执行许可 | 一套/零套均可保留，不凑数；因果设计不能转为关联 |
| 状态与依赖 | 项目状态、具名产物、明确依赖 | 分开的执行/检查状态、不可覆盖的版本、事件历史 | 缺依赖、重复标识、失败/过期依赖拒绝消费 | 修改上游后全部下游过期，旧内容留存 |
| 确认关口 | 完整方案、确认者、理由、证据位置 | 绑定特定方案版本的决策 | 未确认、失败检查、过期、未支持方法均禁止继续 | 变更后原确认不能沿用 |
| 持久化与恢复 | 有效状态 | 原子替换 JSON 状态文件、重载后的状态 | 损坏状态明确失败；中断中的运行转失败并保留原因 | 保存重载、未知状态、运行中恢复 |
| 命令行 | 项目路径及上述参数 | 可读状态摘要、JSON 审计文件、方案及明确决策记录 | 已存在目录不覆盖；错误返回非零状态 | 在临时目录走通 init → audit → plan → approve → status |

所有模块依赖核心契约；审计计算与候选方案内容组织相分离。没有提供审计器或估计器的产物不会自动获得“检查通过”。

## 数据与状态约定

- 执行状态：pending、running、completed、failed、needs_decision、stale、not_applicable。
- 检查状态：pending、passed、failed、needs_decision、stale、not_applicable。
- 每次内容修订保存旧版本，清除当前确认，将全部传递下游标记过期。历史产物只读留存，不得因修订而消失。
- 依赖记录绑定产物版本；消费产物同时检查内容状态、检查状态及全部上游版本。
- JSON 采用严格有限数值；文件采用同目录临时文件写入并原子替换。当前为单进程本地工具，不支持多个写入者并发更新。
- CSV 空白、未披露、不适用、匹配失败等按原始标记计数；只做盘点，不填零、不清洗、不执行合并。
- 方案必须先记录缺失规则、样本、测量版本、模型、固定效应、标准误及理由。支持目标只限描述/关联；因果/预测需求保留为不支持执行。

## 阶段边界与后续顺序

本阶段实现：状态内核、审计、方案契约、版本确认、恢复、命令行、合成样例与自动测试。

下一阶段：从方向与字段说明组织候选方案的交互流程 → 描述统计与单一 Python 固定效应估计器 → 运行参数对照与可复现包 → 判断—证据表 → 接入用户界面。首次完整原型仍须覆盖标准第 9、10 节的闭环，之后再增加方法。

尚未实现：自动文献检索、完整候选生成、合并执行、固定效应吸收检查、标准误与少簇诊断、回归、统计复现、结果解释、真实用户理解度验证。
