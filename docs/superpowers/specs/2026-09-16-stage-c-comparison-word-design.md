# 阶段 C：多模型比较与 Word 结果交付

日期：2026-09-16。基线：0.2.0a3，开发分支 codex/framework-foundation。

状态：用户已确认本设计的首批范围；已进入实施计划编制，功能尚未实施。

## 1. 目标与方案选择

将已有分析运行组织成可比较、可追溯、可编辑的研究结果材料。用户用自然语言指定基准、稳健性和展示顺序，Agent 读取项目材料并完成出表，无需用户编写配置。

比较三条路径：

| 路径 | 收益 | 代价 |
| --- | --- | --- |
| 只增加单次报告的 Word 导出 | 实施最小 | 仍需人工拼表，不能解释模型与样本差异 |
| 统一比较数据，再输出 Word（推荐） | 一次整理即可支持并列表、样本说明和追溯 | 需要新增比较记录与数据契约 |
| 同时接入任意外部回归表和自由模板 | 覆盖广 | 提取误差、状态与版式组合过多，不适合作为首批验收范围 |

采用第二条路径。先覆盖当前已独立核验的线性固定效应结果；为项目脚本保留明确的后续接入边界。

## 2. 首批使用流程

1. 用户提出“把现有基准和稳健性结果整理成 Word”，或指定运行及顺序。
2. Agent 核对当前项目、运行版本、方案、变量含义和核验状态；从研究记录判断已有模型角色，不按显著性选列。
3. 生成比较记录，注明模型角色、排序、展示变量、差异和来源。角色不明确时先完成事实整理，再提出必要的问题。
4. 在同一结构化比较数据上生成预览和可编辑 DOCX，并核对数值与版式。
5. 保存交付文件与依赖记录；新会话可以读取并说明每列对应的运行和待办。

整理现有结果不触发新估计。固定共同样本、增加模型或修改样本，均作为分析方案变更处理，沿用既有授权规则。

## 3. 功能范围

### 3.1 多模型比较

- 支持同一项目内多个当前有效、独立核验通过的线性固定效应运行；Python 和 Stata 可并列。
- 每列记录：标题、基准/稳健性/其他明确角色、方案及运行版本、因变量及变换、解释变量、控制变量、固定效应、标准误与聚类字段、观测数、主体数、实际年份范围和核验状态。
- 按变量身份与定义对应行；同名但定义、单位或变换不同的变量不得静默合并。需明确映射或分表。
- 展示系数、括号内标准误及明确的表注；置信区间和精确 p 值保存在详细结果中。显著性星号可配置，按未舍入的 p 值计算并注明阈值。
- 区分变量未纳入、被吸收/不可估计、缺少统计量与实际零值，不以统一空白或零混淆。
- 仅展示实际存在且定义清晰的拟合统计量；不同口径的 R² 不合并为同一行。
- 不因结果方向或显著性隐藏运行。报告保存纳入列表；明确请求只展示部分系数时注明省略规则，完整系数仍可追溯。

### 3.2 样本及设定差异

- 展示每列样本量、实际企业年度键集合之间的交集与增减数量；样本量相同不能当作同一样本。
- 用现有筛选、完整案例和处理记录解释有证据的差异；缺乏证据的原因标为尚未定位，不从计数猜测。
- 比较数据版本、因变量口径、控制变量、固定效应和推断方式，提醒哪些系数不宜直接比较。
- 不自动将系数变化归因于新增控制变量；样本与设定同时改变时同时说明。

### 3.3 Word 交付

- 默认中文 A4，生成可编辑三线表，含表题、列编号、变量标签、统计行和表注。
- 默认交付模型比较表、样本与设定差异说明、变量定义表及简短结果说明；未知定义明确保留，不自动补造。
- 同口径描述统计复用既有结果；各模型样本不同时，不将某一列的描述统计标成全部模型共同样本。
- 宽表优先横向页面，仍过宽则按模型组拆表并重复关键行；长表重复表头，避免裁切、重叠及不可读缩字。
- 结果解释由 Agent 基于比较数据和研究材料撰写，保留证据来源；工具核对数值引用，不将文字解释自动认证为因果结论。
- 生成 Word 的同时保存机器可读比较记录与可读预览，避免多个输出各自重新计算数值。

## 4. 实现边界与状态

在现有单次报告旁新增三个独立职责：运行结果适配、比较与样本差异计算、Word 渲染。复用 Workspace 的版本、文件校验、依赖和原子发布，不改写原始运行。

比较记录绑定每一项运行的具体版本和实际材料。生成或重新打开时通过现有可用性入口核验；文件变化、上游修订或运行过期，使对应比较及交付记录失效。已导出的 DOCX 是生成时快照，表注或附录保留生成时间、版本和来源，不能承诺外部副本自动更新。

统计核验状态与文档检查状态分开：排版通过不升级统计状态。DOCX 生成、渲染、数值核对和视觉验收分别记录。缺少文档依赖或渲染环境时明确保存实际完成范围；不把未渲染文件称为版式验收通过，不破坏旧报告或原分析。

首批正式比较不接收未核验 script_run 或外部回归表。它们仍可沿现有流程提供执行说明与附件，不冒充正式已核验列。后续扩展需新增明确的结果适配与检查契约，不将“支持多模型”解释为“所有估计方法均已核验”。

## 5. 验收标准

所有软件验收使用临时合成项目，不创建个人研究。

1. 三个有效模型可按指定顺序并列；每个展示数值逐项对应冻结结果，四舍五入及星号边界正确。
2. Python-only 环境完成比较、DOCX、保存与接续；Python/Stata 混合来源单独验收。
3. 样本量相同但观测键不同、增加控制变量造成缺失损失、不同因变量单位或变换，均正确识别并说明。
4. 未纳入变量、不可估计值、零系数和缺少拟合指标不混淆；不能比较的定义不被静默对齐。
5. 未核验项目脚本、篡改、失败和过期运行不能进入正式比较；上游变更使已保存交付过期，旧文件仍保留。
6. 中文标签、长表、多列宽表及跨页表注完成实际渲染和逐页视觉检查；表格可编辑，无裁切、乱码或重叠。
7. 从入口和公开手册发起自然语言任务，完成“基准与稳健性出表—保存—新会话接续”，不依赖读取测试或源码摸索接口。
8. Skills 同步、完整项目测试和普通 clone/ZIP 使用流程通过后，才更新对外能力说明。

## 6. 推进顺序与范围限制

先实现结构化比较与样本差异，再实现 Word 交付，最后更新入口、公开手册及使用验收。阶段 C 不同时扩展 DID/IV 核验、任意外部表格解析、期刊模板库或整篇论文生成。

本设计不要求默认多 Agent 工作。开发在维护分支推进，发布按用户后续授权执行。
