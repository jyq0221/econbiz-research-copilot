# 阶段 B 扩展：可独立使用 Python 的 Stata 接入设计

日期：2026-09-16。

状态：已在开发分支实现，版本 0.2.0a2，实际范围与证据见 [双引擎验收](../../stata-validation.md)。用户选择“Stata 正式回归、Python 独立复核”，并要求支持没有 Stata、只能使用 Python 的用户。

设计时基线：开发分支 5609fb9；公开使用版本 0.2.0a1 仅实现 Python 分析。本次开发实现尚未更新远端 main；下列设计要求及来源保留，验收按实测记录判断。

## 1. 目标与两条完整路径

保留 Python 独立完成研究流程的能力，增加可选的 Stata 正式执行引擎。两者共用方案确认、数据规则、运行包、数值复核、报告和恢复工具。

| 用户环境与选择 | 正式执行 | 独立复核 | 功能要求 |
| --- | --- | --- | --- |
| 没有 Stata，或选择 Python | Python PanelOLS；描述统计用现有实现 | 独立 SciPy 稀疏投影、最小二乘、显式协方差与独立描述统计 | 完成全部当前支持的分析、报告与恢复流程 |
| Stata 可用且用户选择 Stata | Stata 正式估计与描述统计 | 同一套独立 Python 参考算法 | 保留原生 Stata 结果、do-file、日志及完整复核证据 |

独立性来自不同计算实现。Python 正式路径的复核不得再次调用 PanelOLS 或复用其估计对象；Stata 正式路径的复核不得调用 Stata 重算来代替独立参考。

两条路径的结果都必须通过相同统计定义下的检查，才能进入正式报告。不能将 Python 路径标为功能受限、未验证或必须补装 Stata 才能完成。

## 2. 选择与兼容规则

### 2.1 默认与显式选择

- 公共执行接口增加可选关键字 `backend`，值限 `python`、`stata`；默认保持 `python`，现有调用行为不变。
- 不提供根据本机安装情况自动切换的 `auto` 模式。安装了 Stata 本身不改变默认引擎。
- 用户可在研究上下文中保存项目偏好；Agent 读取有效记录后显式传入 backend。一次选择持续适用，无须每次运行重新询问。
- 本轮用户选择的 Stata 优先适用于其明确选择该方式的研究，不改变所有新用户的默认设置。
- Python 路径不探测、不导入、不初始化 Stata 或 PyStata；Stata 安装损坏、缺失或授权不可用不能阻断 Python 路径。

### 2.2 科学方案与执行配置

模型、样本、变量、固定效应、标准误及自由度口径属于分析方案；引擎、可执行文件位置、运行时限及软件版本属于执行配置。执行配置在每次运行前冻结并记录。

在用户已授权使用相应引擎、统计定义完全相同的情况下，跨软件复算可以沿用同一已确认方案，以新 run_id 保存，标为复现运行并关联来源运行。不能仅因换软件而要求重复确认统计方案，也不能机械改写为结果后的探索。

若标准误口径、样本、变量或模型发生实质变化，仍按既有方案修订与确认规则处理。不得因某个软件的结果更显著而更换主要结果。

### 2.3 不可用与失败

- 用户未指定引擎时走 Python；未安装 Stata 不是错误。
- 显式选择 Stata 时，先检查版本、可执行入口与实际启动能力。前置检查失败返回清楚的不可执行原因，不创建完成结果，不静默替换为 Python。
- 若用户已有适用授权允许改用 Python，可在尚未执行时按该授权选择 Python，并记录原因。已经开始的 Stata 尝试保留为失败或待核验记录，Python 必须使用新的运行标识。
- 数值复核失败不能触发自动换引擎并选取通过的结果；应先保存差异并查明原因。

## 3. 架构与模块边界

保持一套工作流：确认方案 → 冻结数据与配置 → 调用所选引擎 → 保存原始输出 → 独立复核 → 接收方再次核对 → 报告与恢复。

| 组件 | 输入与职责 | 输出及边界 |
| --- | --- | --- |
| 现有方案和输入工具 | 已确认方案、登记数据、筛选与缺失规则 | 共用可执行统计定义和预期分析样本 |
| 执行调度 | backend 和冻结配置 | 调用受支持的固定入口；保留原有状态与异常收尾 |
| Python 引擎 | 现有 estimate 接口 | 保持现有统计结果与限制 |
| Stata 环境与进程工具 | 受支持的本机安装、运行目录、do-file | 版本证据、进程状态、原始结果和日志 |
| Stata 结果适配 | 原始矩阵、实际样本、命令元数据 | 统一结果字段及可追溯映射；不替换估计数值 |
| 独立复核器 | 冻结数据、统计定义、实际结果 | 样本、设定和数值的逐项比较及明确覆盖范围 |
| 现有报告工具 | 已完成且复核通过的当前有效结果 | 表格、解释、来源引擎与复核记录 |

现有 numerical_check 将引擎标识固定为 PanelOLS，并包含 Python 特有选项。扩展时将通用统计字段与引擎证据分开校验；期望引擎来自冻结配置，不能信任输出自报的引擎。保留旧结果格式与旧冻结包的读取、核验和重跑路径，不回写历史文件。

## 4. Stata 调用方式

首版采用独立批处理进程及生成的 do-file。官方 PyStata 是后续可选接入方式，不新增为 Python 用户的必需依赖。选择批处理是因为其脚本、日志、原始输出易独立检查，也便于接入现有冻结包。

调用工具负责平台参数和进程生命周期，不通过鼠标键盘控制用户已打开的 Stata。执行工作目录和所有输出位于本次运行包，不覆盖其他项目或已有输出。

超时和取消必须终止本次创建的完整子进程树，再保存失败与部分输出；不能只终止 Python 包装进程而让 Stata 继续写文件。主进程不因系统退出码为零就认定回归成功，须同时检查本次运行标识、Stata 命令返回状态、完整输出和数值复核。

仅冻结项目自身脚本和版本证据，不将 Stata 软件本体或授权文件加入仓库、ZIP 或运行包。环境记录只包含复现所需的版本、构建、平台和相关命令来源信息。

设计时仅发现本机 Stata/MP 应用版本 19.0.068 及命令行入口。实施后批处理实际返回 Stata 19 / IC / Unix，宿主为 macOS arm64；不按应用文件名推断版本类型。Windows、Linux 和其他 Stata 版本分别验收后才列为已支持。

## 5. 统计定义与首批命令

首版两引擎采用同一范围：CSV/指定工作表 XLSX、描述统计、企业/年度单向或双向线性固定效应、传统/HC1/单维聚类标准误、完整案例、保留单例、95% 区间。

- K 包含完整设计秩；HC1 修正为 n/(n−K)，聚类修正为 G/(G−1)×(n−1)/(n−K)。
- 聚类推断使用 t(G−1)，其他使用 t(n−K)。残差自由度、推断自由度、协方差矩阵秩分别记录，不混用。
- Stata 首批验证 `areg` 吸收一组固定效应；双向模型的另一组采用显式虚拟变量。小型参考案例另用 `regress` 显式虚拟变量核对。
- `xtreg, fe` 的 robust 选项不能直接当作当前 HC1 的同名映射。其他命令的默认自由度、单例处理也必须逐项核对。
- 沿用现有线性插值分位数定义，在 Stata/Mata 中按该定义计算并记录实现。不得将 Stata 默认分位数与现有 Python 分位数混作同一统计量。
- 保留当前对完全吸收、共线、非有限值、非正自由度、零残差方差、不连通面板和容量的限制。遇到限制不得自动改变样本或模型。
- 容差保持 rtol=1e−6、atol=1e−8，样本键及计数精确比较。不能在观察差异后临时放宽容差以获得通过。

上述命令路径是实施目标，必须用真实 Stata 数值证明符合规则后才能发布；本设计不把文档相符当作已经数值验证。

## 6. 数据传递与原始结果

保留原始输入字节。共享样本准备后，传递给 Stata 的数值使用足够精度；企业代码、年份键、聚类标签和行标识保留原始语义，另存映射。Stata 内部字段使用受控名称，避免中文、长字段名、保留字与脚本语法冲突。

Stata 须回传实际输入值和实际估计样本，核对传递精度、e(sample)、行顺序与字段映射。不能只将预期样本复制到结果，声称它就是 Stata 实际使用的样本。

估计后立即保存 e(b)、e(V)、实际命令、自由度、聚类数、样本与推断结果；保存结果表后再执行可能覆盖临时统计结果的其他命令。原生矩阵、可独立重跑的 do-file、文本日志与统一结构化结果均登记校验值。

Stata 正式结果和 Python 参考结果分开保存。适配器只转换结构、名称与格式；不得用 Python 参考值填补缺失的 Stata 数值后标为 Stata 正式结果。复核器重新构造模型，接收方继续保留对实际加载输出再次核对的机制。

## 7. 安装、无 Stata 接续与发行

- 核心研究准备功能继续只依赖 Python 标准库；分析依赖仍为现有 analysis 可选安装。
- 当前 analysis 安装方式和固定依赖保持可用，不要求安装 Stata、PyStata 或任何授权组件。
- 在无 Stata 环境中，也可以读取并检查已有 Stata 运行及报告的文件完整性和依赖有效性；不因无法运行 Stata 而抹去历史证据。
- 原 Stata 冻结包的同引擎重跑需要匹配的 Stata 环境。用户可按相同统计定义另建 Python 复现运行，明确记录引擎变化；不能称为原 Stata 运行的同环境重跑。
- 报告说明正式引擎和独立复核方法。两条路径通过检查后的报告地位相同。
- main 与 ZIP 继续交付同一使用文件树；开发说明、测试和实施记录留在开发分支。

## 8. 验收标准

| 场景 | 必须观察到的结果 |
| --- | --- |
| 干净环境只有 Python 和 analysis 依赖 | 实际回归、独立复核、四种报告、恢复和冻结包重跑全部完成 |
| Stata 缺失或安装损坏，选择 Python | 不加载或启动 Stata，Python 完整流程照常通过 |
| 原有调用没有 backend 参数 | 使用 Python，原有统计结果与行为保持兼容 |
| 明确选择 Stata，但前置检查失败 | 明确说明原因，不伪造执行、不静默换引擎 |
| 真实 Stata 可用 | 命令、矩阵、实际输入和样本可追溯，Python 独立复核通过 |
| 平衡/非平衡面板 × 三类固定效应 × 三类标准误 | 两条正式路径分别符合相同统计定义，保留全部比较结果 |
| 中文/空格路径、前导零代码、长字段名、极端尺度 | 正确映射并传递；不能处理时明确失败，不截断或猜测 |
| 单例、完全吸收、共线、一簇、不连通、容量超限 | 与预先规则一致，不能自动改样本或产生虚假通过结果 |
| Stata 零退出码但结果缺失、旧输出或命令失败 | 识别并保存失败，不以退出码替代结果验证 |
| 系数/标准误/原始矩阵/样本/引擎标签被改动 | 实际文件与统计检查能拒绝消费 |
| 超时、取消、复核中断 | 本次进程树停止，失败及已有输出保留，结果暴露历史不丢失 |
| 无 Stata 的电脑接续旧 Stata 研究 | 能读有效材料；原生重跑与 Python 复现的区别说明清楚 |
| 原有冻结包和研究项目 | 可继续读取、检查、恢复；不就地重写旧记录 |
| clone/ZIP 分发 | 无 Stata 的实际安装与使用验收通过；Stata 路径另有真实执行证据 |

无 Stata 的持续测试应模拟 Stata 探测/导入/启动一旦发生就报错，证明 Python 路径没有隐性依赖。实际 Stata 集成测试单独运行；跳过这些测试只能说明环境缺失，不能算作 Stata 支持验收通过。

## 9. 实施顺序与范围

1. 先提取引擎接口与通用结果约定，验证 Python 独立安装和现有流程不回退。
2. 实测 Stata 环境、独立进程、错误与超时处理。
3. 接通 Stata 回归和原始结果保存，按固定定义做独立数值比较。
4. 补齐描述统计及边界测试，接入报告、恢复和 Skills。
5. 分别完成纯 Python 环境与实际 Stata 环境验收，再进行发布检查。

本阶段不接入任意已有 do-file 的自动认证，也不新增 DID、IV、权重、多维聚类或自动模型搜索。原生 .dta 导入及第三方 Stata 命令另行设计，处理存储类型、值标签、扩展缺失值和版本依赖。
