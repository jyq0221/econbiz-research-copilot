# LaTeX 结果导出与 PDF 交付设计

日期：2026-09-18。基线：0.3.0a1；维护分支：`codex/framework-foundation`。

状态：用户已选择“结果导出：把回归表、结果说明和公式导出为 LaTeX，并支持生成 PDF”。用户随后授权开始执行。首版已在开发分支实现；实际检查与范围见 [验收记录](../../latex-validation.md)。

## 1. 使用目标与路径选择

用户可以直接提出“把现有基准和稳健性结果导出为 LaTeX 和 PDF，附上模型公式与结果说明”。Agent 读取已保存的研究材料，生成可编辑源文件和可阅读 PDF，并保存它们对应的分析版本。用户无需填写程序配置。

此前比较了结果导出、完整论文工程、已有文稿维护三条路径，用户选择第一条。本设计只覆盖研究结果交付；整篇论文组织、参考文献数据库、期刊模板库和任意外部 `.tex` 修复不进入首版。

导出实现也有三种方式：

| 方式 | 适用性与取舍 |
| --- | --- |
| 将已有 Word 或 Markdown 转换成 LaTeX | 接入较快，但增加中间转换，表格结构、数学内容和来源校验更难保持一致 |
| 由已核验的结构化结果直接生成 LaTeX（采用） | 复用现有数值与变量映射，源文件与 PDF 能绑定同一份内容，需要新增渲染器和编译记录 |
| 同时接受任意模板和外部 LaTeX 项目 | 灵活，但依赖、编译及内容检查范围明显扩大，留待后续 |

## 2. 首版交付内容

- 支持单个已核验线性固定效应运行，以及已有的多模型比较；Python 和 Stata 来源沿用现有核验边界。
- 导出回归三线表、各模型实际分析样本的描述统计、变量定义、样本与设定差异、结果说明和可选模型公式。
- 系数、标准误、样本量、星号规则及模型顺序沿用当前记录；不得因导出重跑估计或改变数值口径。
- 默认中文，允许明确指定英文。内置表题、表注和说明文字按语言生成；用户提供的文字及变量标签由 Agent 按需求整理，保存新记录后再导出，字段标识和来源保持原样。
- 输出 `main.tex`、可单独复用的 `tables.tex`、`narrative.tex`、`equations.tex`、`sources.tex`、简短 `README.md` 及机器可读交付记录。成功编译时另交付 `report.pdf`。
- 源文件导出与 PDF 编译分别保存，允许稍后对同一份源文件补编译；日志和页面检查材料作为项目内证据保存。

第一版描述统计来自这些已核验回归的实际样本，不新增独立描述统计运行的适配器。表格源文件说明所需宏包，不能保证能直接插入任意期刊模板。

## 3. 数据读取与展示

多模型入口复用 `read_model_comparison` 和 `comparison_display.build_display`，保留当前变量身份、统计值格式、比较顺序及样本差异。语言相关文字抽取为明确的展示标签；原有 Word 和 Markdown 默认输出保持兼容。

单模型入口直接调用 `load_checked_model`，从实际方案取得变量定义和字段身份，构造单列展示数据。未知定义保持未知，不创建虚假的第二个模型，也不改变“模型比较至少两列”的现有契约。单模型单独使用与其内容相符的标题和引导语。

建议公共接口：

- `write_latex_report(workspace, report_id, *, comparison_id=None, run_id=None, narrative_id=None, equations=None, language='zh-CN')`：两个来源参数必须且只能提供一个；保存并返回源文件交付记录。
- `read_latex_report(workspace, report_id)`：重新读取来源、登记字节和展示记录，核对其当前有效性。
- `compile_latex_report(workspace, build_id, report_id, *, executable=None, timeout=120)`：对确定版本的源文件执行编译并保存本次尝试。
- `read_latex_build(workspace, build_id)`：重新核对编译输入、PDF、日志和来源版本，返回真实成功或失败状态。
- `record_latex_review` / `read_latex_review`：对指定成功编译的 PDF 保存并读取逐页检查证据。

单模型默认展示全部解释变量，不新增独立变量筛选或星号配置界面。多模型沿用比较记录中的规则。后续需要单模型自定义出表时另行扩展接口，避免首版出现两套统计展示规则。

## 4. 结果说明与公式

结果说明沿用有来源的 `session_note`。Agent 先核对其中的数字、单位和结论，再保存并引用；排版工具只认证已登记文字的忠实输出，不自动认证自由文本的推导或因果判断。

公式是独立的结构化条目，每条包含 `id`、`title`、`latex`、`explanation` 和 `source_refs`。来源引用使用 `artifact_id` 与 `version`，至少绑定一个当前可用的方案或研究笔记。Agent 从真实设定组织公式并说明变量对应关系；例如单向固定效应运行不能被写成双向固定效应模型。

首版支持独立展示公式中的上下标、希腊字母、分数、根号、求和、常用运算符及括号。普通正文中的字符按文字转义，不能将整段说明直接作为任意 TeX 命令执行。

公式验证器使用允许的数学命令和分组语法，设置长度及嵌套上限；拒绝文件读写、宏定义、环境切换和未知控制序列。验证通过表示语法属于受支持子集；公式的经济含义与设定对应关系仍需 Agent 阅读材料核对。源码中保留原公式与来源记录，编译错误定位到具体公式。

## 5. 排版和编译

采用 XeLaTeX，中文使用 CTeX 与 Fandol 字体配置，减少对特定电脑字体的依赖；英文使用相同编译引擎和英文模板标签。CTeX 官方说明支持 XeLaTeX 和 Unicode 输入；Fandol 提供中文字体，并随 TeX Live/MiKTeX 分发。[CTeX](https://ctan.org/pkg/ctex)、[Fandol](https://ctan.org/pkg/fandol)

表格使用 `booktabs` 与 `longtable`，A4 页面。最多三列模型使用纵向页面，四至六列使用横向页面，更多模型按现有顺序拆表；长表重复表头，长标签换行，避免靠无限缩字容纳内容。这些宏包分别提供表格线及跨页表格能力。[booktabs](https://ctan.org/pkg/booktabs)、[longtable](https://ctan.org/pkg/longtable)

首版直接调用 XeLaTeX，不增加 latexmk、BibTeX 或 Biber 执行链。编译在临时目录中使用已校验的固定文件名与源文件快照；至少执行两遍，最多三遍，以辅助文件稳定及日志无待重编译提示为准。总运行时间默认上限 120 秒，超时通过现有 `processes.run_process` 终止进程组，并保存已获得的日志。

以参数列表启动程序，不通过 shell 拼接命令，显式关闭 shell escape。该选项禁用 TeX 的外部命令执行，但不应被描述成完整操作系统沙箱；本接口只编译受管生成文件及受限公式。[Web2c 官方手册](https://www.tug.org/texinfohtml/web2c.html)

编译器优先使用显式传入的可执行路径，否则从 PATH 查找，保存实际版本与选项。缺少引擎、宏包或字体时保留已成功生成的源文件并记录具体原因，PDF 状态不得写成成功。产品运行时不自动安装 TeX 或联网获取依赖。

LaTeX 源文件生成不新增第三方 Python 依赖，读取正式结果仍需现有 analysis 依赖。新增 `latex` 可选依赖组，仅包含与现有文档检查一致的 pypdf 和 Pillow 版本，用于 PDF 结构与页面证据检查；外部 XeLaTeX 和宏包单独说明。现有 Word 依赖及接口保持不变。

## 6. 版本与状态

新增 `latex_report`、`latex_build`、`latex_review` 三类产物，复用 Workspace 的版本文件、依赖失效与原子发布机制，不覆盖旧报告。

| 产物 | 依赖与记录 | 通过表示什么 |
| --- | --- | --- |
| 源文件交付 | 运行或比较、说明笔记、公式来源版本、全部源文件散列及展示数据 | 已登记文字与统计表忠实生成 |
| PDF 编译尝试 | 源文件产物及全部输入散列、引擎版本、选项、日志、退出状态及实际 PDF | 当前源文件成功编译，PDF 可解析且至少一页 |
| 逐页检查 | 编译产物版本、PDF 散列、按顺序保存的页面图片、观察页码及发现 | 已实际检查全部页面，并明确记录发现 |

源文件的 `completed/passed` 不等于 PDF 已存在；PDF 编译通过不等于版式验收通过。编译错误、超时、缺依赖或 PDF 无法解析均保存失败尝试，保留此前成功产物。每次重试产生新的版本，不借用旧目录残留的 PDF。

严格读取器重新核验源文件与来源；上游变化使相关交付失效，旧文件保留为历史快照。编译收尾再次核对源文件版本和散列，防止编译期间来源改变仍登记成功。失败尝试可读以便定位问题，但不能成为成功 PDF 或逐页检查的输入。

`progress` 的交付入口和恢复上下文纳入这三类产物，分别显示源码、编译和视觉状态，并链接 `.tex`、`.pdf` 与说明文件。研究项目移动后，源文件和已登记 PDF 仍可读取；重新编译时重新探测当地引擎。

## 7. 内容及版式检查

源文件核对不能仅比较同一个渲染函数的两次输出。生成器使用固定的表格/单元格边界，检查器从实际 `tables.tex` 解码受支持的转义与表格结构，逐项对照展示值；同时核对正文顺序、公式内容和来源引用。测试用独立构造的期望数值及篡改样例验证该检查。

PDF 检查结合本次退出状态、实际输出文件解析、页数及日志，不仅判断文件是否存在。缺字、未定义引用、过宽内容和未稳定排版提示均进入发现记录；不能因退出码为零而忽略。严重编译错误判为失败，版式警告要求检查对应页面。

逐页验收需要由宿主将本次 PDF 渲染为 `page-1.png` 起的连续图片，打开全部页面，检查中文、公式、数字、长表、横向页面和表注。观察声明及文件绑定分别保存，不把图片存在解释成已经查看，也不声称自动证明公式的数学含义。缺少页面渲染能力时明确保留视觉未检查状态。

## 8. 模块与实施顺序

1. `latex_report.py`：来源适配、语言展示、源文件组织与保存；复用现有模型读取和展示逻辑。
2. `latex_syntax.py`：文字转义、受支持公式语法和确定性源码片段；不处理估计与项目状态。
3. `latex_runtime.py`：编译器发现、限时执行、日志及 PDF 结构检查、尝试记录。
4. `latex_checks.py`：实际源码核对、严格读取、编译记录读取及逐页证据接口。
5. `progress`、公开结果交付手册、中文/英文 README 和相关研究入口 Skills：让自然语言请求能找到正确接口，明确实际验收边界。

模块间通过结构化展示数据、源文件映射和版本引用传递内容；编译器不负责生成研究解释。只为 LaTeX 接入调整必要的公共展示层，不扩大现有统计方法范围。

维护源为 `.agents/skills/`，修改后同步 `.claude/skills/` 并检查一致性。工作在开发分支完成，公开 main/ZIP 发布沿用仓库的另行发布流程。

## 9. 必须完成的验收

所有软件测试使用临时合成项目，不创建个人研究。

1. 单模型、多模型及 Python/Stata 混合来源导出：数值、顺序、星号、实际样本和来源版本一致；既有 Word/Markdown 行为不回退。
2. 零值、缺项、未知定义、长变量名、特殊字符、中英文和三列/六列/超过六列等内容正确；普通文字不会改变 TeX 结构。
3. 公式的上下标、希腊字母、分数、求和及来源检查成功；未知命令、错误分组、过长/过深公式和来源变更有明确失败结果。
4. 篡改 `.tex`、交付记录、来源、PDF 或检查图片后严格读取失败；版本升级使下游过期，旧文件仍可追溯。
5. 编译器缺失、宏包/字体缺失、非零退出、超时、未产生 PDF、损坏 PDF、重试及编译中来源变化均有真实状态和日志，不影响旧报告。
6. 在真实 XeLaTeX 环境完成中文与英文、长表、宽表和公式的 PDF 编译及逐页视觉检查。模拟编译器测试不能替代此项；引擎尚未配置时不得宣布 PDF 能力验收完成。
7. 重新打开项目能定位实际源文件与 PDF；从公开使用树的临时 clone/ZIP 中完成导出、编译和恢复，项目路径含中文及空格。
8. 完整项目测试、Skills 同步检查及差异格式检查通过；再以实际验收状态更新能力说明。

当前环境观察：2026-09-18 在本会话 PATH 及检查过的常见安装目录中未找到 XeLaTeX。实施阶段已在临时目录配置便携 TeX 环境并完成真实验收，详见验收记录；此初始观察不证明整台电脑不存在其他安装。

## 10. 设计检查与下一步

- 用户所选的回归表、结果说明、公式及 PDF 均有对应输入、输出和验收项目。
- 单模型与多模型路径明确，不借用不存在的比较记录；首版方法范围保持现有线性固定效应边界。
- 生成、编译和视觉检查分别记录，缺编译环境不降格成“PDF 已实现”。
- 用户审阅并授权后已完成实施、自动化检查与原生页面验收；公开发布仍按仓库既有流程单独进行。
