# 使用分支与独立测试数据交付

用户已要求默认 clone 和 ZIP 都不附合成测试数据、开发测试、内部实施记录，并单独给出测试数据下载链接。本次执行该交付调整；回归问题只核对并解释当前能力，不扩展阶段 B。

## 文件与交付

- `main` 使用开发分支归档产生的使用文件树，普通提交保留既有历史。
- `codex/framework-foundation` 保留开发与验证材料；在线文档链接改指该分支。
- `.github/ISSUE_TEMPLATE/trial-feedback.md` 是用户反馈入口，保留在两种使用交付中。
- 合成数据独立发布为 GitHub Release 附件，完整面板 30 家虚构企业 × 2018—2025 年，共 240 行；问题版在副本中加入明确可核对的问题。字段定义、合成来源和使用提示随附件提供。
- README 区分方案/代码草稿/外部结果讨论与尚未实现的正式统计执行和数值复核。

## 顺序与验收

1. 更新分发测试，先确认旧归档缺少发布后仍需使用的反馈入口。
2. 更新归档规则、入口与在线链接，运行全部程序测试、Skill 一致性和差异检查。
3. 在临时目录制作数据附件，用实际 CSV 检查接口和独立计数核对完整与问题版本，确认未知标记、零与重复原样保留。
4. 提交开发分支；把其归档文件树写入隔离的 main checkout，核对移出文件清单并正常提交。
5. 发布数据附件与两个分支，实际重新下载附件、ZIP，并默认 clone 验证两种使用目录的文件字节和保存/接续。
6. 将验证证据只提交开发分支；最后给出使用包、测试数据下载链接及当前回归能力。
