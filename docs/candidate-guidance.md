# 第二阶段：引导式候选方案草案

依据：已确认的设计标准 v1.1，特别是第 4.3、5、7、8 节；沿用用户要求的非技术表达。本阶段不引入估计器。

## 交付与实现取舍

用中文问答引导研究者确认目标、关注现象及实际字段含义；确定性程序根据已确认映射和真实数据覆盖，形成最多两个不同问题的草案，并输出可直接阅读的 HTML 对照报告。保留命令行入口供协助者启动，报告阅读无需编程基础。

与只要求学生填写完整技术方案相比，引导式入口先询问他们了解的数据事实。完整网页交互与外部语言模型接入留给后续阶段；这一轮通过固定的“描述现象 / 条件关联”草案验证数据与方案之间的连接。它不是自由提出新颖研究选题或自动证明文献贡献。

## 契约

- 输入：有效数据盘点版本、研究目标、关注现象与可选解释因素、实际字段映射及逐字段的定义/单位/时间/来源/缺失含义/测量距离/核实状态。
- 数据事实：重新核对原文件哈希；读取原始 CSV；计数关注变量可用观测、双方共同样本、主体及期间、解释变量的企业内原始变化。不修改源文件或执行回归。
- 输出：原研究方向与目标、已知信息、待核实事项、候选草案、具体比较理由、未走通的路线及最小补充需求。每个草案满足已有方案结构要求，但在现有确认接口前仍需研究者审阅。
- 零个方案：目标未确定、因果/预测超出支持范围、关注变量映射尚未核实、没有可用数值等。保留原问题，不改为别的目标。
- 一个方案：描述目标，或关联目标下只有描述路线可准备；明确描述只能回答缩小后的问题，不替代原关联问题。
- 两个方案：描述关注现象与探讨两个已核实指标的条件关联；分别说明不同研究问题，不称为互相验证的稳健性检验。
- 关联草案：必须有两个不同数值字段、至少两个主体和两个期间、共同样本内至少有解释变量企业内变化。通过这些筛查仍不代表固定效应吸收后可识别；该检查在估计阶段完成。标准误标为待研究者论证，草案不能直接取得分析许可。
- 样本规则：仅提出完整案例的候选规则并列出流失数及影响，保留缺失原始状态；研究者确认前不进行样本处理。
- 推荐理由：基于当前测量核实、覆盖和问题范围，直接解释下一步，既不评分，也不读取回归结果排序。
- 状态连接：保存 intake → candidate_comparison → 各 plan 的依赖；这些产物的结构检查通过不代表测量假设认证。方案均保持 needs_decision；修改 intake 后对照和方案均过期。
- 本地 HTML：静态、无网络、全部用户文本转义；显式说明是生成时快照，使用前应从项目状态核实版本。报告包含可读的范围、每条路线、样本事实和下一步，不展示源文件绝对路径或程序对象。

## 验收

验证真实字段、未知目标、不支持目标、无映射、未核实映射、无有效数值、单一路线、两个草案、企业内无变化、共同样本减少、不变更原文件、上游修改传播过期、输入变更阻断、文本转义、问答中“不清楚”与取消、方案登记不自动确认。原有测试必须继续通过。
