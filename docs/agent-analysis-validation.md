## 真实工作流验收

### 自动化集成场景

合成企业年度数据 → 按年缩尾/明确 log1p → Python 项目处理脚本实际运行 → NumPy/pandas 独立处理核对 → 处理后数据与来源运行绑定 → 盘点 → 固定效应正式执行与独立统计复核 → 正式报告。

另执行未在固定估计注册表内的 OLS 项目脚本，实际系数与独立 NumPy 最小二乘参考一致；项目脚本仍保持 `completed/pending`，没有把测试对照升级为通用方法认证。正式固定效应仍为 `completed/passed`。否定处理运行证据后，下游来源、盘点、模型与报告随依赖关系失效。

## 审查发现与修复

规格与质量审查使用额外错误注入及真实原生探针，保留了发现失败的测试：

- 处理来源必须依赖产生它的实际运行，不能只依赖源码；旧来源恢复也遵守这一关系。
- 超时前已打印的输出流写入文件；一个非法输出不会妨碍其他可读证据登记。
- 宿主中断保留可能的结果暴露与失败状态，允许新运行技术重试。
- 显式项目脚本路径才能调用通用运行器；自报 passed 文件不能升级统计状态。
- Python 内部入口/工具路径不泄漏到分析脚本的 argparse 参数。
- 原生数值用可往返的序列化，审计 JSON 合法；UTF-8 错误、无法保真的整数阈值和不支持的派生数值文本操作明确拒绝。
- 主计算与独立参考分别修复大/小量级标准化、常数组均值、固定小数解析及大基数小变化问题；能接受正确值并拒绝伪造零值和错误偏移。

最终预处理复审无待修复发现；项目脚本质量审查所发现的 argparse 问题已用失败→通过测试修复，全套回归通过。

### 推送前追加复核

对 `3f338e7` 进行数值处理和运行状态两项独立审查，发现并修复四处问题；新增五项回归测试均先实际复现失败，再验证修复：

- Stata 对 `.01/.02/.03` 中心化时，中间值可能成为极小正数，影响后续 `> 0` 筛选。保留稳定初始均值并用残差均值修正舍入，不把小数强行归零。
- 原生分位数先加一再取小数部分，使 1% 阈值发生舍入偏移。改为先计算零起点位置，再转换数组下标。
- Python 加权插值与独立 NumPy 线性分位数在 `-.99/-.98` 的四分位点相差一个浮点末位，使后续严格筛选样本不一致。Python/Stata 都从较近端点插值；独立参考仍直接使用 NumPy，样本、键与零值检查不放宽。
- 通用状态修改曾能将项目脚本标成已核验或把失败改为成功。禁止这类升级；消费入口同时核对原始完成状态、待复核状态与统计标记，旧存档中的错误外层标签也不能绕过检查。失败与过期处理仍可正常使下游失效。

数值复审另用 626 行合成数据检查普通正负小数、大基数小变化、极大/极小量级及常数组，最终实际代码通过独立参考。专项测试覆盖实际原生输出、处理后阈值筛选，以及成功/失败记录的状态边界。两项独立复审均无剩余发现；重新打开此前宿主场景的处理和 Logit 运行，101 个文件的散列及执行来源检查通过。
