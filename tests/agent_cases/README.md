# 真实宿主行为验收

cases.json 的十个请求分别覆盖自然语言入口、现有论文、CSV 检查、外部结果、反馈、无数据草案、点名 Skill、跨环节、维护任务和缺少工具。
每项在干净工具副本中用实际宿主执行，不能仅做字符串断言就标为通过。记录日期、系统、宿主和模型版本、实际工具、读取 Skill 的可见证据、实际回复和产物。

## 执行方法

1. 将已固定提交克隆至临时目录。从工具仓库根打开，不从 research-projects 子目录启动 Agent。
2. 逐条发送 request，保留真实工具与输出日志；input_fixture 指向随库合成样例，required_artifacts 必须实际存在且可读取。
3. 以 expected_actions 和 prohibited_actions 人工评审。没有可见读取证据时记“未确认”，不能把正确措辞当成实际调用。
4. 只有创建项目的两个情境可以写入研究目录，其他请求按各自范围执行。测试材料全部为合成。
5. 顺序续接：在 case-concept 保存讨论、更正和任务后关闭写入，另一宿主打开同项目，用 Workspace.open/resume_context 对照来源、版本及下一步。
6. 文件恢复：保存两个来源版本及检查点，改坏最新文件、删除概览、模拟中断；检查无法恢复和仍可恢复的范围，确认不抹去后来历史。

工具测试可自动运行；模型行为需要实际评审。缺 Claude Code、无可用模型会话或没有三名目标初学者时如实记录，继续其他验收，不虚报兼容性或教学有效性。

用户试用关注：能否理解测量/样本变化、是否知道当前没有正式回归、是否能继续上次任务。邀请和发送消息须另有实际授权；本仓库不自动向他人发送邀请。
